# Resultado de aprendizaje: Identificación de sistemas ERP-CRM

## a) Se han reconocido los diferentes sistemas ERP-CRM que existen en el mercado

Durante las actividades realizadas en clase, investigamos diferentes sistemas de planificación de recursos empresariales (ERP), sistemas de gestión de relaciones con los clientes (CRM) y otros sistemas de gestión especializados.

Un **ERP (Enterprise Resource Planning)** es un sistema que permite gestionar de forma integrada los datos y los procesos de una empresa. Entre sus funciones se encuentran la gestión de inventarios, productos, usuarios, empleados, almacenes, facturas, logística, incidencias y distintas sedes de una empresa.

Entre los ERP analizados se encuentran SAP S/4HANA, Microsoft Dynamics 365, Oracle Fusion Cloud ERP, Oracle NetSuite, Odoo, Sage, Infor CloudSuite, Workday, IFS Cloud, Acumatica, Epicor Kinetic, SAP Business One, Microsoft Dynamics 365 Business Central, ERPNext y Dolibarr.

Por otro lado, un **CRM (Customer Relationship Management)** es un sistema destinado a gestionar las relaciones con los clientes, especialmente en el ámbito comercial y de ventas.

También investigamos los sistemas PMS (Property Management System), utilizados en la gestión de establecimientos hoteleros. Algunos ejemplos estudiados fueron Mews, Cloudbeds, Oracle OPERA Cloud, RMS Cloud, Guestline, RoomRaccoon, Stayntouch, WebRezPro, protel, Beds24, eZee Absolute, Hotelogix, Sirvoy, Little Hotelier y Apaleo.

## b) Se han identificado los diferentes tipos de licencia de los sistemas ERP-CRM

En clase estudiamos diferentes tipos de licencias de software, entre ellas GPL, propietaria y Apache.

- **Licencia GPL:** permite utilizar, estudiar, modificar y distribuir el software de acuerdo con las condiciones de la licencia.
- **Licencia propietaria:** el propietario mantiene el control sobre el código y establece las condiciones de uso. El cliente puede recibir una copia del programa compilado o acceder al servicio mediante una suscripción.
- **Licencia Apache:** es una licencia de software libre y de código abierto que permite utilizar, modificar y distribuir el software conforme a sus condiciones.

También analizamos el modelo de Odoo, que permite acceder al código fuente de determinadas versiones y realizar instalaciones y personalizaciones, teniendo en cuenta las condiciones de licencia correspondientes.

Además, aprendimos la importancia de revisar el clausulado de las licencias, las garantías, los términos del servicio y el pliego de condiciones antes de utilizar o desarrollar una solución empresarial.

## c) Se han comparado sistemas ERP-CRM en función de sus características y requisitos

Para mi proyecto he optado por desarrollar una plataforma SaaS multi-tenant que integre funcionalidades de PMS, CRM y GMAO para la gestión hotelera.

La arquitectura tecnológica propuesta estará formada por un backend desarrollado con Node.js y Express, una base de datos relacional MySQL, una interfaz web desarrollada con React y una aplicación móvil nativa para Android mediante Kotlin.

Esta combinación permitirá centralizar la información de los hoteles, gestionar las habitaciones y los huéspedes, asignar tareas al personal y realizar el seguimiento de las incidencias de limpieza y mantenimiento.

La elección de MySQL responde a la necesidad de almacenar información estructurada y relacionada, mientras que Node.js permitirá desarrollar la lógica del servidor y ofrecer una API para comunicar la aplicación web y la aplicación móvil.


## d) Se ha identificado el sistema operativo adecuado a cada sistema ERP-CRM

En las actividades realizadas estudiamos la arquitectura cliente-servidor y la diferencia entre el entorno del cliente y el del servidor.

En el lado del cliente, la aplicación puede utilizar una interfaz web desarrollada con HTML, CSS y JavaScript, a la que se accede mediante un navegador. Este enfoque permite utilizar la aplicación desde equipos con Windows, macOS o Linux, siempre que dispongan de un navegador compatible.

En el lado del servidor, estudiamos el uso de Linux como sistema operativo dentro de una arquitectura LAMP, formada por Linux, Apache, MySQL y PHP. También se contemplaron alternativas basadas en PHP o Node.js.

Por tanto, la elección del sistema operativo del servidor depende de los requisitos del ERP-CRM, de las tecnologías empleadas y de la compatibilidad con sus componentes. En los apuntes no se especifica un sistema operativo concreto para cada uno de los productos comerciales analizados.

## e) Se ha identificado el sistema gestor de datos adecuado a cada sistema ERP-CRM

Durante las actividades realizadas en clase estudié diferentes gestores de bases de datos, entre ellos MySQL, PostgreSQL, SQLite y MongoDB.

Para mi proyecto he elegido MySQL como gestor de base de datos principal, ya que necesito almacenar y relacionar información sobre hoteles, usuarios, habitaciones, huéspedes, preferencias, empleados y tickets de mantenimiento.

Al tratarse de una plataforma SaaS multi-tenant, el diseño de la base de datos deberá permitir identificar a qué hotel pertenece cada registro y garantizar que cada establecimiento solo pueda acceder a la información que tiene autorizada.

Además, la aplicación Android podrá utilizar Room Database para almacenar localmente la información necesaria cuando no haya conexión a Internet. Posteriormente, los cambios podrán sincronizarse con el servidor cuando se recupere la conectividad.

De esta manera, MySQL centralizará la información de la plataforma, mientras que Room permitirá gestionar la persistencia local de la aplicación móvil.

## f) Se han verificado las configuraciones del sistema operativo y del gestor de datos para garantizar la funcionalidad del ERP-CRM

Para garantizar el funcionamiento de mi sistema de gestión hotelera, será necesario configurar y comprobar los diferentes componentes de la arquitectura cliente-servidor.

Las principales verificaciones previstas serán:

Backend: verificar la instalación de Node.js, las dependencias y el funcionamiento del servidor desarrollado con Express.

Gestor de datos: comprobar que MySQL esté instalado, que el servicio se encuentre activo y que permita establecer conexiones.

Conexión con la base de datos: verificar que el backend pueda conectarse a MySQL mediante las credenciales correspondientes.

Estructura de la base de datos: comprobar la creación de las tablas, las relaciones y las restricciones necesarias para gestionar la información hotelera.

Aislamiento de datos: verificar que cada hotel únicamente pueda consultar y modificar sus propios registros.

Control de acceso: comprobar que los permisos de los usuarios se apliquen correctamente en las operaciones realizadas desde la web y la aplicación Android.

Persistencia y sincronización: comprobar el almacenamiento local de la aplicación móvil y la sincronización de los cambios con el servidor cuando vuelva a haber conexión.

Estas comprobaciones permitirán detectar posibles errores de instalación, conexión, permisos o funcionamiento de la base de datos. Los resultados se documentarán a medida que se realicen las configuraciones y las pruebas.
